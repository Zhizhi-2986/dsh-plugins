# Workspace Files V0.1 verification

The v0.0.1 base is released. This change set covers tree/list/read, double-click edit, save on close/Ctrl-or-Cmd+S/blur/button, Markdown preview, in-file find, global-search dropdown with line navigation, Quick Open, empty-file creation, preview-confirmed literal global replacement, and folder expand/collapse controls. Interaction is verified in a jsdom environment against the compiled Client components; these changes have **not** been exercised inside a running installed DSH plugin.

## RED → GREEN evidence

- Search byte accounting: 17 one-byte opaque files first caused a false truncation before a later text match; Host now charges byte length from the actual read, even for binary contents. A second regression grows 33 opaque files after listing and verifies actual read bytes still trigger the aggregate cap.
- Glob filter work: new tests first failed because filtered files bypassed the candidate limit and large combined glob filters were accepted; search now caps combined filter text at 512 characters and counts candidates before matching filters.
- File creation: the new Host integration test first failed with `service.createFile is not a function`; after adding the session-scoped `createIfAbsent` path, it passes duplicate-target, traversal, symlink-parent, missing-parent, size, session-policy, and sandbox checks.
- Global replacement: the multi-file draft-race test first showed an unintended write to `b.txt` after its buffer became dirty during the first write. Per-file preflight checks now skip the changed file and preserve drafts; the race and partial-version-conflict tests pass.
- RPC completeness: contract tests first showed the Host descriptor missing `createFile` and stripping search `truncated` metadata. Host/Client descriptors now match; search and Quick Open truncation metadata survive schema parsing.
- Replacement allocation: oversized per-file/aggregate output tests reject before constructing the full output; dense-match tests exercise bounded 1,024-part chunking rather than retaining one reference per occurrence.
- Incomplete search: oversized-file tests first showed skipped 1 MiB+ text files did not set `truncated`; search now marks both metadata-known and read-time oversize skips incomplete, and Host integration proves the metadata reaches the Client.
- Replacement excerpts: tests exercise replacements whose text already occurs earlier in the file and empty-string deletion; UI preview remains anchored at the original match offset.
- Tree cascade: the new recursive Expand All test first missed the nested file after a prior Collapse All. Sequenced actions and scoped cascades fix recursion without replaying after manual toggles; tests cap each action at 10 directory loads and 2,000 descendant rows, show the budget notice, refresh without consuming the budget twice, and confirm manual expansion reveals the rest.
- Tree RPC failures: a rejected list promise first left the row loading and surfaced an unhandled rejection; `finally` clears loading and the panel shows a localized error.
- Canonical create paths: a path-guard regression first returned `docs/../docs/new.md` for a backslash dot-segment alias on POSIX. Separators are now normalized before dot-segment resolution; Host tests verify both slash styles return canonical paths, which the Client uses for selection/opening.
- Path work bounds: Host rejects paths over 1,024 characters before segment checks, and Typert Client/Host schemas share the same cap to bound link-triggered and direct RPC work.
- Buffer race/version: when a draft appears during a successful replacement write, tests verify the draft stays dirty while its base `savedContent` and version advance to the new disk version.
- Error safety: an unknown local filesystem error initially leaked `/Users/alice/private/workspace` to the client; Host IO errors now return only a generic operation failure.
- Optional-atom search regex and single unbounded quantifier tests failed against the earlier regex guard; both pass with the conservative no-quantifier subset.
- Repeated wildcard glob filter `'*'.repeat(14) + 'Z'` against a 48-character filename took ~1.47 seconds and failed the <150 ms regression. The linear-state matcher passes and preserves `src/**/note.ts` semantics.
- Session-bound RPC tests originally routed session A's delayed save to selected session B; now every FilesView's API is bound to its session identity, and both single-save and Close-All regressions pass.
- Search bounds first returned silent partial success, then were made hard errors, which broke searching any workspace containing a lockfile. They now keep prior results, stop the outer traversal at file/byte/directory/result caps, account observed sizes for opaque files, cap combined glob filters at 512 characters and count filtered file candidates against the scan cap, bound the pending-directory frontier at 2,000, and report `truncated`; Quick Open also caps its pending frontier at 2,000 and propagates partial-result status to its dialog.
- UI tests initially failed until each event used the path React actually delegates: native bubbling `dblclick` for double-click edit, `Simulate.change` for controlled inputs, and `focusout` for `onBlur`.
- View-tab key regression (2026-10-23): the initial test failed at Digit6 because the handler only accepted 1…5. It now accepts Digit1…Digit9 and the full nine-tab interaction passes.
- Duplicate settings regression (2026-10-23): the screenshot showed ten catalog rows for five actions. A regression test failed with `10 !== 5`; the final implementation removes configurable shortcut registration entirely, leaving a fixed default input handler and no shortcut-setting rows.
- Desktop routing (verified by reading the installed app): its preload exposes `dshDesktop.protocolVersion` but no native keyboard bridge or `html[data-platform]`; the service runs in Web transport. The plugin listens to `observeFixedInput` only when the Desktop marker and macOS platform are present. Native key delivery still requires a manual live-app check.
- Input safety tests ensure Option+Shift is the only consumed combination, and that modal, composition, prevented events, and terminal focus are ignored.
- Reorder RED → GREEN (2026-10-23): CSS visual-order shortcut test first failed because Digit1 targeted the first DOM button instead of the visually first Files button, then passed after visual-order resolution. Opt-in settings-card test first failed (`1 !== 2` checkboxes), then passed after the toggle was added. Read-only drag test first failed (`draggable: true`), then passed after writable gating. Duplicate-tablist test first returned an arbitrary Tab, then passed after a fail-closed count check. Post-drag click test first leaked activation from the drag source, then passed after suppressing only the browser-generated source/target click and clearing the guard on the next pointerdown. Drag/persistence tests initially could not import the not-yet-created `tab-reorder.js`; after implementation and a corrected test fixture, the targeted tests passed.

An absent Digit5/9 Tab initially consumed editable input; tests first failed, then passed when the fixed-input handler stopped consuming nonexistent positions.

## Known gaps and security limits

- An earlier build of the linked plugin has been installed in the user's DSH Desktop profile, and screenshots confirmed the Files view renders. **This create/global-replace/expand-all build was not installed or enabled in that profile.** The Option+Shift+1…9 handler is verified through jsdom and the installed shell routing, but actual macOS key delivery and drag behavior have not been observed in a running Desktop; jsdom cannot prove native key delivery, actual drag/click sequencing, Desktop chrome, or the CDN Monaco path.
- Native Tab buttons have no stable view-ID attribute, so the experiment checks registered IDs/labels/counts against the original DOM sequence. A host update, localized label mismatch, or nonstandard header can disable reordering. CSS visual order does not change DOM reading/focus order; this is not an accessibility-complete feature.
- New modal dialogs use `aria-modal` and autofocus but do not yet trap keyboard focus or restore focus to the trigger; keyboard focus behavior was not tested.
- Existing Monaco loader code is fetched from jsDelivr; Markdown previews can make external HTTPS image requests. These pre-existing runtime trust/privacy behaviors are not changed by this feature.
- The installed DSH 0.2.1-rc.2 filesystem backend uses path-based targets and lacks operation-time no-follow workspace confinement for reads and mutations. Concurrent symlink swaps between path validation/canonicalization and read/create/write remain possible; `createIfAbsent` only protects the final target name. This is an upstream/backend limitation outside the authorized plugin-only scope. Do not use this build with untrusted concurrent workspaces.
- Branch coverage for `buffers.ts` (61.5%) and `path-guard.ts` (69.2%) is below 80%; TSX coverage is measured only through the compiled component tests.
- No Desktop profile installation, pull request, or publication was performed for this validation.
